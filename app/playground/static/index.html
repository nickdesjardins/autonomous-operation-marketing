Applied AI · LangGraph · human-in-the-loop

Copy that ships only after a human says yes.

Pick a product and give a campaign brief. A supervisor validates the request, an inventory tool reads the SKU from PostgreSQL (no model writes SQL), a synthesis agent drafts the channel copy, and a compliance validator audits it against Health Canada NHP rules: a model's verdict, plus deterministic checks that a model cannot talk its way past. A draft with violations goes back to the synthesis agent, at most as many times as you allow. Then the graph pauses on a checkpoint and waits for you.

Nothing leaves until you decide. Approve, edit or reject the draft below. Approval fires one HMAC-signed webhook; in this demo the service posts it to its own receiver, which verifies the signature and keeps what it received.

    Models
    
    
    The pipeline calls free OpenRouter models, in an ordered chain: the next model is tried only when a call fails, never on a wrong answer. With no models named in the settings, the service looks after the chain itself: it reads the chain this project's scheduled test published, and after a failed request it tests the free models with its own three cases (a draft, an audit that must catch planted violations, an audit that must pass a compliant draft) to fill a place a withdrawn model left.

    How a run flows
    
    
    Six nodes, one cycle, one breakpoint. After a run, the nodes it visited are highlighted below.
    
    
    
      
      
    1. Supervisor. Validates the request (SKU code, channels, brief, revision budget), resets the revision counter, and routes: to the inventory agent on a fresh thread, straight to synthesis when the inventory is already loaded, to END when the request is invalid.
      2. 
      
    2. Inventory SQL Agent. One parameterized, read-only lookup of the SKU. No model is involved: a SKU lookup is not a decision a model should make. An unknown SKU or a stock of zero ends the run here.
      3. 
      
    3. Copy Synthesis Agent. A model drafts the title, product page, five marketplace bullets, a social post, an image prompt, the disclaimers and the NPN, under a strict JSON schema. On a revision it receives the previous draft and the exact violations to fix.
      4. 
      
    4. Compliance Validator. A model audits the draft against the rules; then Python checks what can be checked deterministically (NPN present, no prohibited claims, licensed amounts, mandatory risk statements verbatim). A finding from the checks is a violation whatever the model said.
      5. 
      
    5. Human Approval Gate. Marks the thread as waiting. The graph is compiled with interrupt_before=["webhook_dispatch"], so it stops on a checkpoint right after this node, with everything persisted in PostgreSQL.
      6. 
      
    6. Webhook Dispatch. The only mutation. It refuses to send unless the human review status is approved or edited, validates the copy once more, signs the payload with HMAC-SHA256 and delivers it with retries. Every attempt is written to the audit log.

      The rules
      
    
      Modelled on Health Canada's framework for Natural Health Products. The auditor is told these rules; the deterministic checks enforce the ones that can be checked mechanically. This is a demo, not legal advice.

      The prompts
      
    
      Both system prompts are static strings. Everything that varies goes in the user message, and the campaign brief travels inside tags with a random suffix, declared untrusted: a brief that says "ignore your rules" is data, not an instruction.
